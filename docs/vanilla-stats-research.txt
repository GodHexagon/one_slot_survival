## Player Events in Forge

Forge provides events for various player actions including attacking entities, interacting with blocks and items, entity deaths, and player jumps.

### Jump Events
The LivingJumpEvent can be used to detect when a player jumps, which fires on both client and server side.

### Block Break Events
For detecting block breaking, you can use BlockEvent.BreakEvent which provides access to the block state and the player. Block break events are registered with MinecraftForge.EVENT_BUS.register().

### Block Place Events
The search results mention block placement events exist alongside break events for tracking when players place blocks.

### Attack/Click Events
For player attacks on blocks, the attack() method is called when a player left-clicks on a block. For entity attacks, you can subscribe to the AttackEntityEvent and check the entity type.

### Movement
Player movement can be modified through Forge modding, though the search results focused more on tutorials about modifying movement mechanics rather than specific movement detection events.

The results primarily cover older Forge versions (1.7.2-1.17.x). For Minecraft 1.21 specifically, you may need to check the latest Forge documentation as event names and registration methods may have changed.

方式1: Forgeイベントベース
プレイヤーのアクションを Forge の各種イベントでフックして経験値を付与する。 対応イベント:
歩行/走行/ジャンプ: LivingEvent.LivingTickEvent または PlayerTickEvent で移動距離を計算
ブロック破壊: BlockEvent.BreakEvent
ブロック設置: BlockEvent.EntityPlaceEvent
アイテム使用: LivingEntityUseItemEvent.Finish
攻撃: AttackEntityEvent
キル: LivingDeathEvent (死亡原因がプレイヤーか判定)
盾で防ぐ: LivingDamageEvent または LivingAttackEvent (盾でブロックしたか判定)
メリット:
Forgeの標準的な手法
MOD間の互換性が高い
バニラコードに手を加えない
デメリット:
イベントごとに個別実装が必要
移動距離の計算は毎tick呼ばれるため、パフォーマンスに注意が必要
一部のアクション(盾で防ぐ等)は複雑な条件判定が必要
方式2: Mixin による awardStat のフック
バニラの ServerPlayer#awardStat メソッドをMixinでフックし、統計情報の更新を検知して経験値を付与する。 実装概要:
@Mixin(ServerPlayer.class)
public class ServerPlayerMixin {
    @Inject(method = "awardStat", at = @At("TAIL"))
    private void onAwardStat(Stat<?> stat, int amount, CallbackInfo ci) {
        // statの種類に応じて経験値を付与
        if (stat == Stats.WALK_ONE_CM) {
            // 歩行の経験値付与
        } else if (stat == Stats.JUMP) {
            // ジャンプの経験値付与
        }
        // ... 他の統計情報も同様
    }
}
メリット:
バニラの統計システムを再利用できる
すべてのアクションを一箇所で管理できる
バニラがすでに実装している判定ロジック(走行/歩行/泳ぎの区別等)をそのまま利用できる
コード量が少ない
デメリット:
Mixinへの依存(すでにプロジェクトで使用中なので問題なし)
バニラの統計システムに依存するため、バニラの変更に影響を受ける可能性
方式3: ハイブリッド方式
一部のアクションはForgeイベント、一部はMixinで実装する。 使い分けの例:
Forgeイベント: ブロック破壊、ブロック設置、アイテム使用、攻撃、キル
Mixin: 移動、ジャンプ、盾で防ぐ(バニラの統計を再利用)
メリット:
それぞれの手法の利点を活かせる
Forgeイベントがある場合は標準的な手法で実装できる
複雑な判定が必要な場合はバニラの実装を再利用できる
デメリット:
実装が分散する
どちらを使うか判断基準が必要

推奨: 方式2 (Mixin による awardStat のフック)
以下の理由から、Mixinによる実装を推奨します:
実装の簡潔さ: すべてのアクションを一箇所で管理できる
バニラの実装の再利用: 複雑な判定(走行/歩行/泳ぎ/しゃがみ歩き等の区別)をバニラのロジックに任せられる
保守性: 新しいアクションを追加する場合も、統計情報の種類を追加するだけで済む
プロジェクトとの親和性: すでにMixinを使用しているため、新たな依存関係が不要
パフォーマンス: バニラの統計更新のタイミングで動作するため、余分な処理が発生しない
実装イメージ
@Mixin(ServerPlayer.class)
public class ServerPlayerMixin {
    @Inject(method = "awardStat", at = @At("TAIL"))
    private void onAwardStat(Stat<?> stat, int amount, CallbackInfo ci) {
        ServerPlayer player = (ServerPlayer)(Object)this;
        
        // 統計情報に応じて経験値を付与
        if (stat == Stats.WALK_ONE_CM) {
            // 歩行距離 100cm = 1ブロック毎に経験値
            ExperienceManager.addExperience(player, amount / 100.0);
        } else if (stat == Stats.SPRINT_ONE_CM) {
            // 走行はより多くの経験値
            ExperienceManager.addExperience(player, amount / 100.0 * 1.5);
        } else if (stat == Stats.JUMP) {
            // ジャンプ1回毎に経験値
            ExperienceManager.addExperience(player, 1.0);
        } else if (stat.getType() == Stats.BLOCK_MINED) {
            // ブロック破壊
            ExperienceManager.addExperience(player, 5.0);
        } else if (stat.getType() == Stats.ITEM_USED) {
            // アイテム使用
            ExperienceManager.addExperience(player, 2.0);
        } else if (stat == Stats.MOB_KILLS) {
            // モブキル
            ExperienceManager.addExperience(player, 10.0);
        } else if (stat == Stats.DAMAGE_BLOCKED_BY_SHIELD) {
            // 盾で防いだダメージ量に応じて
            ExperienceManager.addExperience(player, amount / 10.0);
        }
        // ... 他の統計情報も同様
    }
}
